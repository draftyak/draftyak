# ICS to free-slot goldens

These synthetic inputs have literal expected UTC intervals and local display
labels in `cases.json`. Expectations are not generated by the engine or renderer.
Each case names a feed, fixed clock, UTC window, owner zone/working hours, busy
intervals and final slots. Optional horizons use the real working-day window
builder before feeding its output into the composition.

The first twenty-two cases cover RRULE/RDATE/EXDATE and overrides, all-day and
floating values, status filtering, all six scheduling-zone DST transitions,
midnight and fractional offsets, clipping, rounding/minimum neighbors, twelve
slots and YEARLY expansion/COUNT cutoff. Existing synthetic provider and DST
feeds in `../fixtures/` are reused. The YEARLY pair pins three literal starts
from the merged engine's `yearly-hours` case without reading an external oracle.

Three additional weekday cases start Friday 23 October 2026 at 08:07 UTC. Their
window anchor is 08:00; the fresh one-hour lead rounds upward to 09:15. The
3/5/10 working-day windows end at midnight on 28 October, 30 October and
6 November respectively. A weekday recurrence makes occupied and free output
nonempty; the ten-day case additionally observes the twelve-slot cap.

The all-day case deliberately has no availability. Every other literal success
in `cases.json` requires nonempty slots. `ICS_CANARY_*` event fields and fixture
addresses must remain absent from engine, checked and rendered outputs. Malformed, unknown-zone and
oversized feeds are errors, never empty availability.

Run `pnpm --filter @draftyak/calendar-goldens test`. Native broker/fetch,
credentials, process, authorization, prompt/log persistence and owner-session
acceptance remain separate. The package test task is uncached so every external
feed change is observed.
