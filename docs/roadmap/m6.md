# M6 backlog: Slack

M6 connects Slack through the native approval, broker, sync and retention paths.
The pure channel package provides deterministic rendering, request-profile and
outcome classification, supplied-fact preflight comparison and conversation-fact
decoding. Native services depend on M2/M3, with device UI after M4. Native,
live-session and owner acceptance are separate milestone gates.

## Ownership and inputs

`plugins/channel-slack/**` owns the pure component and its credential-free
synthetic fixtures. This includes exact request bytes and hashes, machine-text
escaping, the narrow request profile, send-outcome classification, preflight
comparison and strict `conversations.info` fact decoding. It consumes the merged
protocol contracts and the existing fake package. Production imports are Node
builtins and the protocol's hash and normalized-change modules; test fixtures
also use the shared JCS parser and fake transport.

Native account, broker, executor, sync, retention and UI paths require coordinated
ownership in their respective milestone work. Callers derive inputs from the
frozen revision/snapshot, establish approved authorship before selecting owner
markup, obtain complete current facts, enforce routing and mint/consume the
one-use broker ticket. A decoded fact or transport callback supplies no approval,
freshness, identity or posting authority.

## Channel-facts codec

`decodeSlackChannelFacts(expectedChannelId, response)` returns immutable
`SlackChatFacts` using the shared channel types and existing scalar/preflight
rules. The envelope must have own enumerable data fields `ok:true` and
`channel`. The channel requires these explicit own enumerable data fields:

| Fields | Admission |
|---|---|
| `id` | Valid channel ID exactly equal to the requested ID |
| `name` | Nonempty, well-formed, control-free text, at most 256 UTF-16 units |
| `num_members` | Integer from 0 through 1,000,000,000 |
| `is_channel`, `is_group`, `is_im`, `is_mpim` | Primitive booleans with exactly one true |
| `is_private` | Primitive boolean; legacy groups, DMs and MPIMs must be private |
| `is_archived`, `is_member` | Primitive booleans preserved without inferring posting permission |
| `is_shared`, `is_ext_shared`, `is_org_shared` | Primitive booleans; external or organization sharing requires shared status |
| `is_pending_ext_shared` | False; the output cannot express the pending transition |

Modern channels use `is_private` for public/private type; legacy groups map to
private, IMs to `dm` and MPIMs to `group_dm`. ID prefixes supply neither missing
type facts nor identity. Optional `is_ext_ws_shared` must be a primitive boolean;
true requires both external and shared status. Optional `is_frozen`,
`is_read_only` and `is_thread_only` must be primitive booleans and refuse when
true because the output cannot represent those restrictions. Absent optional
restrictions are not evidence that posting is allowed.

The projection inspects two plain records and a fixed selection of scalar
descriptors. Proxies, accessors or inherited needed fields, arrays, exotic
prototypes and malformed scalars refuse with fixed
`SlackCoreError("INVALID_INPUT")`. Unneeded topic, purpose, message and identity
branches remain unread. Native transport must bound response bytes and parse
them safely before invoking this codec.

Sparse DM/MPIM responses refuse rather than inventing membership, names, count
or false flags. Callers should request `include_num_members:true`; every other
required fact must still be present. A complete synthetic DM/MPIM fixture checks
the explicit mapping without proving that a provider read supplies all facts.
Provider references are Slack's [conversation object](https://docs.slack.dev/reference/objects/conversation-object/),
[`conversations.info`](https://docs.slack.dev/reference/methods/conversations.info/)
and [legacy MPIM object](https://docs.slack.dev/reference/objects/mpim-object/).

## Native handoffs and gates

The renderer emits an explicit primitive `reply_broadcast` for every request;
true requires a valid thread timestamp. Native composition must obtain that
frozen broadcast value and the owner's acknowledgement, approval and provenance
independently. Machine or MCP contributions require escaping the entire body;
provider text or client assertions cannot select owner markup.

The executor re-renders from the approved revision, compares body/header hashes
at claim and passes exactly those UTF-8 bytes through the one-use broker ticket.
The native adapter's request representation must agree with the pure renderer,
including the broadcast field. Headers are the fixed frozen content-type pair;
native credential injection and transport authority remain broker-owned. The
128 KiB request ceiling requires a blob/reference path when a carrier's frame
limit is smaller.

The hub owns the two-clock window and undo predicates, account mode, epoch,
approver and policy checks; ten-second bounded claim-time info/history/replies
reads with limit 20; durable monotonic inbound watermarks and the final
transactional hold-if-reply check. Failed or incomplete reads retry on a later
tick and eventually miss the window. Per-channel one-second pacing and at most
30 scheduled items per channel per five minutes belong to the native scheduler.

Only trusted broker evidence can establish that no request byte was written.
Possible writes, lost responses and ambiguous outcomes require reconciliation,
without automatic resend. Retry classification preserves server waits and the
delivery deadline; it creates no timer or durable state transition itself.

Installation/disclosure, credential storage, Socket Mode or polling, tier
budgets, normalization, history/replies decoding, revocation cancellation,
retention, export, native UI and complete FakeSlack composition remain their
work items above. S6/ADR 0008 and the owner's policy confirmations gate live
behavior. Pure component checks cannot satisfy those gates.
