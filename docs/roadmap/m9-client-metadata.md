# M9 CIMD and JWKS destination guard

This slice adds an unmounted native destination guard and bounded HTTPS GET implementation. It is based on plan §6's CIMD/JWKS allowlist and SSRF boundary and the M0 handoff requiring exact client-ID URLs or configured path prefixes, a capped 30-second failed-lookup memory and rate limits before client lookup. The independent reviewed port starts at `origin/m9` commit `5fbaf89` and restores only the metadata modules and tests from `4059414`. Its private package exports the fetcher and its configuration/result types; runtime dependencies are Node builtins and the already merged protocol JCS parser. No remote listener, native store, M1.8/M1.19 contract, authorization server or provisional authority stack is included.

`ClientMetadataFetcher` requires explicit `destinations`, `deniedAddresses`, `maxBytes` and `timeoutMs`. There are no built-in vendor hosts, client IDs, paths or allow-all defaults. An explicitly empty destinations list denies everything. CIMD and JWKS permissions are distinct and match the entire lowercase host plus an exact path or a non-root directory prefix ending in `/`. A prefix cannot accidentally match a sibling such as `/clients-other/`. Configuration is copied as plain data before reads, rejecting accessors, proxies, sparse arrays, extra fields and serialization hooks.

CIMD has fixed purpose ceilings of 5 KiB (5,120 bytes) and 2,500 ms for the entire DNS/TLS/response operation. This explicitly interprets the plan's 5 KB as `5 * 1024` bytes. Effective limits are the minimum of these ceilings and configured limits. JWKS keeps its existing configurable 1 MiB and 10,000 ms ceilings. Configuration cannot relax CIMD limits. The pinned HTTPS helper independently enforces both CIMD ceilings; the outer deadline still includes DNS and does not restart at connection time. Monotonic deadline and cancellation checks run again after local cache processing and final byte copying, so late data or continuations are refused even before a delayed timer callback runs. Eligible untrusted bytes may already have entered the bounded cache before this final refusal; cache admission grants no authority.

Composition must load these rules from actual owner-approved security state. Adding or widening a rule is an admin operation; this slice implements no setter, persistence or approval route. On tightening, policy replacement, exposure shutdown or hub lock, close the old fetcher before applying the new state; close aborts its in-flight DNS/HTTPS operations and refuses future work. `deniedAddresses` is mandatory and must include the hub's advertised/public/tunnel IPs even when absent from local interfaces. The resolver additionally checks every current local interface address. The destination port is always 443; explicit ports, including hub and inspector ports, are refused.

The URL grammar deliberately permits only canonical lowercase `https://`, ASCII DNS labels with at least two labels, and an explicit absolute path made of ASCII unreserved characters and `/`. Host suffix matching, wildcards, IP literals, numeric host aliases, userinfo, query, fragment, explicit ports, percent escapes, Unicode, backslashes, repeated slashes and `.`/`..` path segments are refused. A WHATWG parse must preserve the complete original string. This conservative grammar may need an owner-reviewed extension if ADR 0006's actual client documents require more; it does not guess vendor URLs.

DNS uses a fresh cancellable native resolver for A and AAAA, checks all returned addresses, and rejects an empty or over-32-answer set. It blocks private, shared/CGNAT, loopback, link-local, multicast, reserved, documentation and transition address ranges, including every IPv4-mapped/compatible IPv6 address and NAT64. IPv6 is limited to ordinary global-unicast space with conservative special-use exclusions. These exclusions are informed by the [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry/) and [IANA IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry/) registries. Public exceptions inside a blocked special-use range remain refused. The Azure platform address `168.63.129.16` is also denied because it reaches [host-platform services](https://learn.microsoft.com/en-us/azure/virtual-network/what-is-ip-address-168-63-129-16). This is an application guard, not a guarantee about arbitrary host routing or transparent network interception; owner-managed networks must not route ordinary public destination addresses to private services.

HTTPS connects only through the validated address supplied by its lookup callback, with no second DNS resolution or fallback. It verifies the normal certificate chain and hostname, sends the original hostname as SNI and Host, and checks the connected socket's remote address before writing HTTP bytes. It uses a new non-pooling agent with TLS session caching disabled and an explicit empty `proxyEnv`, so proxy environment variables supply no destination or credentials. These are native [Node HTTPS agent/request options](https://nodejs.org/api/https.html#new-agentoptions). There is no caller-controlled CA, socket, hostname override, header set, method or body.

Requests are credential-free GETs with only Host, Accept, Accept-Encoding identity and Connection close. No cookie, bearer credential, referrer, client assertion or original OAuth request is forwarded. Every status except 200 is refused, so redirects are never followed. Response headers and error bodies never escape. The response must have a single JSON media type (JWKS may use `application/jwk-set+json`), optional UTF-8 charset and no compression. Ambiguous content length/type, oversized declared or streamed bytes, incomplete responses and byte-count mismatches are refused. Configuration accepts `maxBytes` within 1–1,048,576 and a timeout within 1–10,000 ms, subject to the tighter purpose limits above. Response headers remain capped at 16 KiB.

At most eight fetches run concurrently, and the same purpose/URL cannot run twice concurrently. Failures retain only a SHA-256 key of purpose plus URL for 30 seconds on a monotonic clock, capped at 1,024 entries. Eligible successful bytes now have bounded, instance-local reuse under the [metadata cache rules](m9-metadata-cache.md); nothing is persisted. An observed monotonic rollback permanently closes the instance. All refusals have the fixed message `Client metadata refused`, with no URL, address, response body, header or nested transport error attached.

The returned `MetadataBytes` contains only bounded untrusted bytes and their accepted media type. There is no merged CIMD or JWK document acceptance contract on this base, so this slice does not validate client metadata fields, accept a JWKS, register or authenticate a client, follow its `jwks_uri`, choose redirects, mint tokens or claim an OAuth success. A later adapter must run every CIMD and JWKS retrieval through this guard and validate documents against the accepted contract. Before any lookup it must enforce the authorization/token/revocation routes' per-IP limits. ADR 0006, exact provider integration and the owner's live connector checks remain gates; no live vendor request was made here.

The suite covers URL normalization, owner-rule isolation, getters/proxies, special-address and mapped-IPv6 matrices, mixed DNS answers, own addresses, rebinding pins, TLS/SNI/Host settings, peer refusal before HTTP writes, redirects, size/compression/truncation, failed-cache expiry/capacity, in-flight caps, DNS cancellation, response timeout, premature request close and monotonic rollback. A request close before response end refuses immediately and frees its concurrency slot; a successful response ends before request close in [Node's documented event order](https://nodejs.org/api/http.html#httprequestoptions-callback). It does not claim a real TLS handshake, conformance, a mounted OAuth integration or the M9 gate.
