# M9: remote MCP

M9 follows M8 and M4. Its complete acceptance includes the public listener and
issuer, device-approved consent, connector token lifecycle, the SSRF matrix,
route isolation, deployment guides and owner-run clients. The current slice
implements only the bounded transport part of M9.4 and the pure ingress helpers
of M9.5. No listener, issuer or authorization server is mounted.

The remote OAuth design, M9 milestone and OAuth AS test strategy in the approved
plan govern this backlog. M0's live-connector ADR 0006 remains open. Product code
imports no spike modules, and synthetic tests confer no owner authority.

| Item | Inputs and owned paths | Output and acceptance |
|---|---|---|
| M9.1 remote MCP composition | Accepted M8 dispatch, M4 paired devices; future native composition and route tests | Correct resource audience and current native grants on every request; isolated public route snapshot. Open. |
| M9.2 public authorization server | Reviewed S4 handoff, encrypted store and wrapped keys; `apps/hub/src/oauth-as/{provider,adapter,metadata,keys,tokens}.ts` and tests | S256, exact redirect/resource/issuer binding, opaque tokens, refresh rotation and reuse revocation, form bodies and endpoint completion under ten seconds. Open; final connector behavior waits for ADR 0006. |
| M9.3 number-matching consent | Accepted consent contract, paired device and PIN; `apps/hub/src/oauth-as/consent/**` and desktop tests | Bind client, redirect, scopes and selected accounts; CSRF/CSP, push and denial limits. Open. Consent cannot approve a send. |
| M9.4 client discovery | Explicit owner-approved destination rules, hub addresses and cancellation; `apps/hub/src/oauth-as/client-metadata/**`, shared `apps/hub/src/net/**`, `apps/hub/test/client-metadata/**` | Bounded untrusted CIMD/JWKS bytes through one resolve-then-connect guard. This slice delivers transport and cache only. Document validation, redirect policy, persistence, DCR window and AS integration remain open. |
| M9.5 public serving | Explicit canonical public origin, trusted proxy CIDRs and actual native request/socket observations; `apps/hub/src/listeners/l3/**`, `apps/hub/test/peer-policy.test.ts`, `apps/hub/test/proxy-facts*.test.ts` | This slice delivers CIDR parsing and origin-form/Host/proxy facts only. Mounted route policy, per-IP/client limits, public doctor, enablement, alerts and kill switch remain open. |
| M9.6 connector and deployment gate | Real AS plus explicit fake clients, guide and gate documents | Exercise CIMD, issuer on success/error, resource audience, rotation and reuse revocation against the real AS. Then owner-run public clients, real device approval and deployment checks. Open. |

For M9.4 and M9.5 the acceptance commands are:

```powershell
pnpm install --frozen-lockfile
pnpm --filter @draftyak/hub test --maxWorkers=1
pnpm --filter @draftyak/hub typecheck
pnpm --filter @draftyak/hub build
pnpm verify
pnpm guard
```

The [boundary appendix](m9-boundaries.md) specifies the limits, cache rules,
shared-network handoff, native observation contract and composition duties.
The actual candidate must pass these commands before submission; earlier branch
counts and ignored local logs are not acceptance evidence for changed source.
A PR reports the final checked commit and results together.

The pure CIDR and forwarding rules are conservative building blocks. ADR 0006
must settle their deployment use and exact client needs before L3 activation.
The consent page must remain outside the optional MCP/token CIDR filter. No
vendor host, client ID, trusted proxy or allowed CIDR is enabled by default.
