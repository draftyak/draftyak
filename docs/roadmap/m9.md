# M9: remote MCP

M9 follows M8 and M4. Its acceptance includes the isolated public listener,
issuer, desktop-approved consent, connector token lifecycle, SSRF matrix,
deployment guides and owner-run clients. The bounded metadata transport and
pure ingress helpers are components; they do not establish a mounted listener,
authorization server, deployment or genuine-client acceptance.

This is the canonical M9 backlog. All implementation and gate rows remain open
until their own checks pass on the actual merged dependencies. The remote OAuth
design and OAuth AS suite in the approved plan govern it. Product code imports
no spike modules. Synthetic tests confer no owner authority.

### Required details within the item scopes

- **M9.1:** owns `apps/hub/src/listeners/l3/composition.ts`,
  `apps/hub/src/listeners/l3/status.ts`,
  `apps/hub/test/l3-composition*.test.ts` and `apps/hub/test/l3-status*.test.ts`.
  M9.5 owns the other L3 ingress and exposure files. `/status` is static:
  no inputs, identifiers, cookies, script or per-request data, strict CSP and
  `frame-ancestors 'none'`. Only session-pending URL elicitation depends on
  S3's conformance decision. Its retry always runs the complete current pipeline.
- **M9.2:** owns `apps/hub/test/oauth-as/**`. Access tokens last 60 minutes;
  the grant lasts 90 days, each refresh rotation starts a new 30 days, and no
  refresh can outlive the grant. Do not impose a separate 30-day absolute cap
  on the family. These follow ADR 0006's kept refresh tests; any changed lifetime
  requires the owner's decision. Keep grants, tokens, consumed refresh tokens
  and assertion replay records until their expiry; an evicting cache cannot
  erase revocation/replay evidence. Interaction creation is bounded and limited
  before expensive work. `consent.v1` is consumed from the merged M1 contract.
  Use M2's generic restore/namespace contract to revoke this namespace's grants
  and tokens and retire provider profiles after the restore epoch change;
  exercise that behavior in M9's N suite. M10 later composes the actual
  two-machine restore with M9 present.
- **M9.3:** owns `apps/hub/test/oauth-consent*.test.ts`. The signed consent
  binds every displayed field: client, redirect host, scopes, typed number,
  selected accounts, requester IP as displayed or its absence, user agent as
  displayed (at most 256 characters), and versions of every applicable channel
  disclosure and the repeat-what-it-reads warning. M4.13 supplies the trusted
  display/signing path; no device approval shape is invented here.
- **M9.4:** also owns `apps/hub/test/client-metadata/**` and
  `apps/hub/test/helpers/metadata-tls.ts`. Generate test certificates and keys
  at test time. The M2.17 guard must preserve configured/actual non-loopback
  hub-address denial, loopback exceptions only for declared local rules,
  mandatory hub/inspector/transient ports, complete special-use ranges and
  pinned TLS connections. Metadata fetches never permit local destinations.
  Keep policy classification distinct from connection permission. Deny
  redirects/compression/oversize/truncation/stalls, use one shared in-flight
  operation with independent cancellation, and shut it down on lock, epoch or
  policy change. The 5,120-byte CIMD cap comes from the retained provider/S4
  behavior; 2,500 ms is the pinned provider's outbound-fetch default, including
  JWKS. A five-second JWKS ceiling cannot extend the caller's shorter signal.
- **M9.5:** owns `apps/hub/test/peer-policy.test.ts`,
  `apps/hub/test/proxy-facts*.test.ts`, `apps/hub/test/l3-exposure*.test.ts`
  and public-doctor tests beside its check modules. The public-origin and
  trusted-proxy facts come from the actual native request target, headers and
  socket. Absolute-form targets fail before provider audience computation.
  M2.1 owns the hub manifest/configuration/index scaffold; only agreed export
  and dependency additions extend it. Exposure handlers use their own files
  under `apps/hub/src/api/public-exposure/`, with one shared router registration.
- **M9.6:** also owns `tools/verify/profiles/m9.ts`, one root `verify:m9`

## Acceptance command sets and availability

the frozen lockfile, run every touched package's tests, typecheck and build,
changed-file lint, the item's applicable acceptance commands and `pnpm guard`
with zero findings. CI supplies the full suites, including Windows. For changed
verification/CI controls, run every affected check locally with boundary attacks
and mutation proofs, keeping the required test exclusions; use exact-head
full/Windows CI for unrelated suites. A blanket local `pnpm verify` is not a
submission prerequisite. Branch integration retains local default checks with
those exclusions. Review uses CI only under
[the CI verification guide](../ci-verification.md), with the current submission
rules taking precedence over its historical local-full-check wording. Missing,
empty or skipped suites are not passing evidence. No component result completes M9.

`required`, `pr-title` and reviewed-head `review` checks. Review enables automatic
integration; DCO remains separate until the milestone sign-off. Contract changes
belong to their M1 items and must be merged before M9 consumes them.

## Decisions and integration handoffs

- M0 owns ADR 0006: assertion audience, client CIMD-or-DCR choice, server
  default scopes, token-check ordering and forwarded client IP behavior. Do not
  choose these from fixture defaults or enable remote exposure ahead of them.
- S3's proposed session-pending fallback requires the owner's M0 decision.
  Preserve both plan clauses in the coverage below until settled; a proposed
  ADR does not silently remove `/status`/URL acceptance from the plan.
- The owner decides recorded-document `DATA_ONLY` permission. Until then,
  synthetic stand-ins remain offline controls and no recorded vendor document
  is copied into code. S11/S12 and SMS disclosures apply only if approved.
- M2 owns the initial hub scaffold and shared network guard. M9 adopts the
  actual merged exports without adding another address table. M9 consumes
  M2's merged generic restore/namespace contract and adds its own OAuth schema,
  grant/token revocation, profile retirement and namespace-specific tests in
  M9. Resolve namespace/layout ownership before collecting existing
  provider/native code. M10 later composes two-machine restore after M9 reaches it.
- M8 owns dispatch, local bridge/token setup and the local portion of
  `docs/guides/mcp-clients.md`; M8b owns passive artifacts and view checks.
  M4 owns trusted approval/signing. M9 coordinates the remote consent/exposure
  UI and grant-principal extension with those owners, preserving the same gate.
- `tools/verify`, workflow registrations, shared CLI registration and any
  desktop paths require explicit owned implementation items before edits. The
  coverage table records those gaps; no broad directory claim authorizes them.
