## Command and ownership conventions

Each item is a ready PR into `m11` with only its declared paths; related items may share a coherent PR. Use the current remote base, frozen installation, touched-package checks, applicable acceptance and `pnpm guard`. Changes to controls that decide what runs, skips or passes require affected local checks, hostile/boundary inputs and meaningful mutations with mandatory exclusions. Exact-head CI supplies unrelated suites. No blanket local `pnpm verify` is required before an item PR; integration and milestone verification retain their applicable full checks. Missing, skipped or failed evidence is not a pass. Approval applies to the submitted commit, and a changed head needs review again. DCO remains open until owner milestone sign-off.

Commands below are **acceptance obligations, not results**. In coverage tables, a bare launch-check name such as `community`, `privacy` or `threats` denotes exactly `pnpm --filter @draftyak/launch-checks --fail-if-no-match <name>`; it is not a new root script. `pnpm verify`, `pnpm guard`, `pnpm adr` and `node tools/verify/verify.ts --profile docs` exist. The working launch-check package is introduced by M11.2a; the docs app and `pnpm verify:m11` are introduced by M11.3 and .15. Later `docs`, `community`, `privacy`, `threats`, `performance`, `migrations`, `issues`, `terms`, `runbook` and `candidate` scripts are added only with real implementations. Postponed `templates`/reference work adds no placeholder script or empty module. Missing required commands or inputs fail closed.

Each check owns its named module, CLI entry and tests; `src/<module>.ts` uses `tools/launch-checks/test/<module>.test.ts` unless a separate test path is listed. M11.2a establishes package/config/README files. Later owners append only their implemented script; M11.3 additionally owns its docs-check export, exact dependencies and README section. Serialize shared-file edits after preceding merges, regenerate locks normally and preserve unrelated importers/resolutions/edges. No shared CLI registry or root dependency change is implied. M11.1's community entry consumes M11.2a metadata. Every result binds current source/artifact versions and refuses missing, stale or unrelated evidence.
