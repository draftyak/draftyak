# M11 CI rollout addendum

This addendum records the CI rollout into the M11 integration branch. The broader
M11 backlog, community documents and owner launch acceptance retain their existing
ownership and requirements.

## M11.90 Windows PR verification and compact receipts

- **Goal.** Apply the CI verification and review rules from #110 to M11 without
  importing M1 product contracts or changing launch content.
- **Inputs.** The owner-approved CI reuse decision; M11's existing M0-based CI;
  the local verification requirement; [the verification guide](../ci-verification.md).
- **Outputs.** Windows default verification on ready non-doc PRs, with container
  service warm-up and `TURBO_CONCURRENCY: '1'`; pinned checkout
  identities in each contributing job; one bounded JSON receipt and Actions
  summary per completed report, with explicit failures and skips. Preserve this
  branch's existing Linux build and touched-spike heavy-test selection. Review
  reuse requires the guide's author/origin, verification-control path, current
  head/base-tip and selected-coverage checks. GitHub job records remain the
  authority for execution results.
- **Owns.** `.github/workflows/ci.yml` only for Windows selection, container-service
  warm-up, default verification's `TURBO_CONCURRENCY: '1'` and
  receipt metadata/report/upload; `tools/ci-checks/src/{verification-receipt.ts,
  verification-receipt.test.ts,workflow-policy.ts,workflow-policy.test.ts}`;
  `docs/ci-verification.md`; the CI guide map row and verification-during-review
  rule in `AGENTS.md`; this addendum. Existing classifier, package, dependency,
  launch and product paths remain with their current owners.
- **Acceptance.** Frozen installation, `pnpm verify` and `pnpm guard` pass before
  ready submission. The ci-checks package tests and typecheck pass. The actual
  ready PR run has passing required jobs, Windows default verification and a
  receipt matching its current head, base tip and tested checkout. A changed
  base requires a new PR event. DCO and owner launch acceptance keep their
  existing rules.
- **Handoff.** Coordinate the fixed single-file, seven-day receipt upload with
  the ADR 0001 owner before the milestone gate. Installable builds remain outside
  permitted workflow artifacts; this item records the follow-up and leaves the
  ADR with its owner.
