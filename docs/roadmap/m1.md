M1.1d names draft runs' aggregate `required (draft)`, so on m1 and the branches that take m1 only a ready run's `required` counts; M0.3d (#122) puts the same line on m0, from which m11 and, at the M0 gate, main take it.
- **MCP serving** (M0.14, PR #12; `spikes/s03-mcp-sdk/src/server.ts`, `stdio.ts`). SDK 2.3.1 serves the 2026 era with `createMcpHandler(factory, {legacy: 'reject', responseMode: 'json'})` and a fresh `McpServer` per request. `serveStdio(…, {legacy: 'reject'})` answers a 2025 `initialize` with the readable unsupported-version error and keeps the connection. `capabilities.extensions` merges through `mergeCapabilities`, and `McpServer` declares `listChanged: true` unless `false` is passed. M1.12 and M1.14a build on this.
- **In-memory harness** (M0.14; `spikes/s03-mcp-sdk/test/harness.ts`). A 2026-era request carries the `_meta` envelope (protocol version, client capabilities, client info) plus `MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name`, base64-sentinel-encoded when not header-safe; undefined header values are dropped and `''` is sent. M1.14a copies it.
- **Plugin argv and spawn** (M0.11, PR #11; `spikes/s02-plugin-sandbox/src/argv.ts`, `spawn.ts`).
  - The never-list also holds `--experimental-ffi`, `--experimental-sqlite`, `--allow-fs-vfs`, `--experimental-vfs` and `--vfs-load`.
  - `node:sqlite` `ATTACH` bypasses the permission model on both Nodes, so `--no-experimental-sqlite` is the defence.
  - Grant paths must be absolute, with no `*`, `?`, `,`, `=` or leading `-`, and the plugin, data and runtime dirs must be disjoint: none may equal or sit inside another.
  - Plugins spawn with cwd at the plugin dir, stdio `['pipe','pipe','pipe','ipc']` and an environment built from nothing (on Windows PATH, USERNAME, SYSTEMDRIVE and WINDIR are blanked); the pre-spawn link scan fails closed.
  - Still open: whether `--freeze-flags-after-init` joins the allowlist (M0.12, ADR 0003).
- **S12 segmentation** (M0.36, PR #10; `spikes/s12-sms/src/segments.ts`, `vectors/segments.v1.json`). 34 draft vectors. When an escape pair straddles a part boundary, `calculateLength` counts 2 parts where `divideMessage` returns 3. NFD input sizes as UCS-2, so the hub normalizes to NFC first. On a subscription that sends in the 3GPP2 format, one-part texts size differently: printable ASCII is one 7-bit ASCII part at one septet a character, and other one-part GSM-7 text goes UCS-2; the vectors carry 3gpp2 alternatives, and the M0.36 handoff asks the hub and the host to model the format or take the host's (D16). The reference finds grapheme clusters with `Intl.Segmenter`. M0.38 compares all of it on the owner's phone.
- **Pairing EKM parameters** (M0.36's stand-in tests). Label `EXPERIMENTAL-draftyak-pair-v1`, context the 16 raw `pid` bytes, length 32. M0.21's draft evidence shows rustls' exporter equal to Node's both ways on win32-x64; it hasn't merged yet.
- **Temporal** (M0.8's runs, PR #9). `typeof Temporal` is `'object'` on both 26.5.1 and 26.12.0, so "Temporal missing" means `typeof Temporal === 'undefined'`, never a `'function'` check.
- **MIME hashes** (M0.28, PR #14; `spikes/s08-gmail/src/mime.ts`). The reconcile hash `textSha256` (the normalized text part) is not a ticket's `bodySha256` (the exact request body); the protocol keeps the two names apart. Reconcile compares addresses with ASCII (punycode) domains on both sides.
- **CI routing** (M0.3, PR #3; `tools/ci-checks/src/changes.ts`, `.github/workflows/ci.yml`). `changes` fails when a Rust workspace lies outside every spike package; `full` runs heavy tests only for touched spikes; caches are saved only on `main`, and `crates/` reaches `main` only when `m1` merges, so every M1 PR's Rust build is cold. M1.1 changes the first two.
- **Workspace policy** (ADR 0001's kept test, PR #7). Every `package.json` is `"private": true` except under `templates/`, `fixtures/`, `vectors/` and `vendor/`; versions are exact, but the test also accepts a bare exact version for a workspace package; nothing in `apps/`, `packages/` or `plugins/` imports a spike, so M1 copies what it absorbs; pnpm's release-age, build and trust settings are fixed (`minimumReleaseAge: 1440`, strict; `allowBuilds: {}`), so a dependency younger than 24 h, or one that needs a build script, fails the install.
- **TypeScript 7** (ADR 0001, V4). Relative `.ts` imports need `rewriteRelativeImportExtensions` (set), and `isolatedDeclarations` is on. TS 7's root export is only `./lib/version.cjs`, so a tool that loads the TypeScript API needs a TS 5 or 6 alias. M1.2 confirms that tsdown, whose declaration output works from isolated declarations, needs no such alias.
- **Tests that read outside their package** (M0.6b, PR #7). Turbo replays a cached pass unless the package's `turbo.json` lists those files as inputs, as `tools/ci-checks/turbo.json` does; `tools/verify`'s `test` task isn't cached.
- **vendor-guard** (M0.4, PR #8). Fixtures may not hold vendor-issued JWT shapes or the forbidden config paths, in any file; tests build such values at run time. Phone numbers are flagged only in spike evidence, so nothing would stop a real number in `spec/vectors/` or a protocol fixture (Conventions: SMS data).
- **Biome on generated JSON** (Biome 2.5.15, this review). A schema written by `JSON.stringify(schema, null, 2)` fails `biome ci`, because Biome collapses short `enum` and `required` arrays. M1.1 excludes `spec/**/*.schema.json` before M1.2 writes any.
- **Packing** (pnpm 11.28.6, this review). `pnpm pack` turns `workspace:*` into the bare version (`0.0.0`), packs private packages and applies `publishConfig.exports`. pnpm 11 ignores `pnpm.overrides` in `package.json` (with a warning) and then fetches the bare version from the registry, while `overrides` in the project's own `pnpm-workspace.yaml` resolve to the `file:` tarballs. Turbo's `--filter=...{./<dir>}` selects a package's dependents, devDependencies included.
- **npm names** (registry, 2026-10-17). The `@draftyak` scope doesn't exist yet (`Scope not found`), and `@draftyak/protocol` and `create-draftyak-plugin` return 404; creating the npm org is still pending (§16, D15).
- **Unicode data.** Node 26.12.0 ships ICU 78.3 with Unicode 17.0. unicode-normalization 0.1.25 and unicode-segmentation 1.13.3 carry Unicode 17.0; unicode-normalization 0.1.26 carries 18.0.
- **Conformance CLI** (0.2.0-alpha.12). Server mode takes only `--url`, so testing a plugin that speaks stdio needs a loopback HTTP bridge (M1.15b).
- **Merging** (ADR 0001). GitHub's rebase-merge adds no `Signed-off-by`; item PRs are rebase-merged. `pr-meta` accepts an item branch only into its own `mN`, and `mN` only into `main`.

Each pins exact versions, depends on other workspace packages only through `workspace:*` (M1.1's test; the `@draftyak` scope is unclaimed on npm, so a bare version there would resolve from the registry), never imports a spike (it copies what it absorbs and names the spike path in its PR), exports TypeScript source to the workspace (`"exports": {".": "./src/index.ts", "./*": "./src/*.ts"}`) with `publishConfig.exports` mapping the same subpaths to tsdown's `dist/` for `pnpm pack`, takes its test tiers from `vitest.shared.ts` (`heavyVitestConfig` from M1.1), and adds a package `turbo.json` when its tests read files outside the package. Wildcard subpath exports mean a new module never edits a shared `package.json` or index file.
- **Spec and vectors.** Schemas are zod in `@draftyak/protocol`, exported to `spec/` by `pnpm --filter @draftyak/protocol spec` and never edited by hand; a drift test fails otherwise. Vectors in `spec/vectors/<area>/` come from `pnpm --filter @draftyak/protocol vectors`; recorded signatures are kept while they still verify, so random node:crypto signatures don't churn. Generators live in `scripts/vectors/<area>.ts` or `scripts/vectors/<area>/<part>.ts`, each writing its own files, so an item extends an area by adding a file. Vectors that depend on data tables record their versions (tzdata, Unicode). Spec prose under `spec/` is a draft until the M1 gate and passes `pnpm guard`; afterwards it changes only through contract PRs (§12, §4 Versioning).
- **SMS data** (§15 S12: other people's message text, numbers and names never reach tests or fixtures). SMS bodies in vectors and fixtures are invented or `DYTEST-` texts. Numbers come only from fictional ranges: NANP 555-0100 to 555-0199 in any area code, and the UK's 07700 900000 to 900999. From the owner's phone, only ADR 0014's derived results (encodings, part counts, which path the phone took) are used, never the owner's or anyone else's numbers or text. M1.23 tests it.
- **Rust.** One Cargo workspace at `crates/` (`Cargo.toml`, `Cargo.lock`, `deny.toml`). Direct dependencies are exact `=x.y.z` requirements, and `Cargo.lock` is committed and used with `--locked`. `pnpm verify` runs `cargo fmt --check`, clippy with `-D warnings`, the tests and, where installed, cargo-deny. A shared `CARGO_TARGET_DIR` under `DRAFTYAK_CACHE_DIR` stays optional, as in M0.
- **Size.** M0's counting applies, plus a `generated` category for `spec/**/*.schema.json` (M1.1). Several M0 items passed ~1,500 counted lines once review fixes landed, so M1 plans an L item at about 1,200 counted lines, splits the largest up front (M1.14a and M1.14b), and splits at review rather than waiving the limit.
- **Machine.** M0 items keep priority. Instead of a worktree count, M1 follows resource rules:
  - TS-only items run whenever a worktree is free; M1.1–M1.3 are TS-only and start now beside wave C.
  - At most one cargo- or Docker-heavy M1 run at a time (a cargo build, the cross tests, process-mode suites, the template smoke, `verify:m1`), and only with at least 6 GB of RAM free.
  - No M1 install, build, test or verify run starts while the kit's bench lock (`%LOCALAPPDATA%/draftyak-dev/bench.lock`; `bench.lock.owner` names the holder) is held, or while M0.10, M0.12 or M0.35 run their benchmark suites: a benchmark's idle check needs CPU below 20% for 5 s within 240 s or it fails as `machine-busy`, and M0.35's budgets feed the S11 decision. `verify:m1` waits for the lock itself (M1.1); no M1 test takes it.
- **No live secrets or vendors.** No M1 item reads `.env.live` or calls a vendor; every upstream is `@draftyak/fakes`.

## Risks for M1
| Risk | Mitigation |
|---|---|
| Syncing `m1` with a moving `m0` churns open PRs and the lockfile | Sync only when a gated item needs an ADR or M1 needs an `m0` fix, at most once per M0 wave; ready PRs merge first; the lockfile recipe; local `pnpm verify` before every force-push; D14's merge alternative |
| ADR 0003 slips (it needs M0.12, then macOS run A1 in M0.13), holding M1.12–M1.17 | M1.12 splits: its transport-independent parts (the context, `ctx.fetch` over a `HostChannel` interface, errors, `memoryHost`, `createPluginServer`) start before ADR 0003, with M1.13 after them, while `ipcHost`, the host-channel framing and `serve` wait |
| An ADR changes something an early item built on | "Now" items avoid everything an open spike tests and take wave C's findings as inputs; gated items wait for their ADR; ADR follow-ups land every change before M1.25, which lists each ADR |
| S11 or S12 is a no-go | M1.22–M1.24 are dropped; manifests keep refusing `runtime: "python"` (`RUNTIME_UNSUPPORTED`) and the closed-to-plugins values (`CLOSED_TO_PLUGINS`); the gate report lists the clauses removed |
| TS and Rust disagree on JCS or signatures (number formats, escapes, surrogates, duplicate keys, high S) | Safe integers only in signed forms; RFC 8785 and edge vectors; both sides refuse duplicate keys while parsing, since serde_json_canonicalizer alone refuses them only while serializing; fast-check cross tests through `xcheck`; recorded node:crypto and RFC 6979 signatures; a high-S vector |
| TS and Rust use different Unicode data for NFC or grapheme clusters | Crates pinned at Unicode 17.0 as Node 26.12.0's ICU is; cross tests assert the versions match; vectors record them; Node and the crates move together |
| jiff and Temporal disagree (tzdata versions) | M1.18 waits for ADR 0015's comparison; vectors record both tzdata versions; Rust flags a mismatch, as §8 asks of the approval window |
| ICU (`Intl.Segmenter`), unicode-segmentation and Android's BreakIterator disagree on clusters | Vectors from the owner's phone (M0.38, ADR 0014); the host refuses a mismatch (`SEGMENT_MISMATCH`), so a disagreement fails closed |
| tsdown or rolldown misbehave with TS 7 or under pnpm 11's strict builds | Checked first, in M1.2; fallback: `tsc` emit with isolated declarations for libraries, tsdown only for plugin bundles |
| The MCP SDK would serialize tools differently from the canonical entries | The SDK serves `tools/list` from the protocol's literal entries; JCS equality is tested in M1.13 and M1.16 |
| A bundled dependency reaches code generation under `--disallow-code-generation-from-strings` | zod jitless, the cfWorker validator, no ajv; process-mode contract tests run every plugin under the production argv |
| An internal package resolves from the public registry, where the `@draftyak` scope is unclaimed | `workspace:*` for every internal dependency (M1.1's test); the smoke's overrides live in its own `pnpm-workspace.yaml`, and its lockfile must resolve every `@draftyak/*` package to a tarball; no npm fallback; the owner creates the org (D15) |
| A real phone number or text reaches a vector or fixture | The SMS data convention; M1.23's range test |
| CI minutes run out beside M0's | The budget and push rule; local heavy runs before each PR; heavy suites selected per change; D17 |
| Worktree and CPU contention with M0's benchmarks | Resource rules instead of a worktree count; heavy M1 runs wait for the bench lock, and `verify:m1` waits itself; no bench lock in M1 |
| PR size overruns after review | L items planned at about 1,200 counted lines; the testkit split up front into M1.14a and M1.14b; split at review instead of waiving |
| Scope creep into M2–M9 (renderer, verifier, broker, MCP tools, bundle checks, the SMS classifier) | "What M1 does not build"; only types, pure validators, SDK and testkit code, and vectors |
| Contract churn after M1 merges | Spec is a draft until the M1 gate; afterwards only contract PRs, under §4's versioning rules |
