## Changed since the plan (verified facts and owner decisions)
- **Public CI and verification reuse (owner decision, 2026-10-19).** The repository became public on October 19. Ready PRs run CI's full suites and reviews may reuse those results after the trust, current-revision and coverage checks in [the verification guide](../ci-verification.md). M0.3b applies the Windows PR checks and compact receipts from #110 to this branch without importing M1 product contracts or changing M0's spike selection. The local `pnpm verify` before ready submission and the live/device/owner gates remain required.
- **Merge rule and auto-merge (owner decision, 2026-10-19).** A branch rule on `main` and every milestone branch requires `required` and `pr-title` from GitHub Actions and a `review` commit status that the integration owner sets on the reviewed head; GitHub then auto-merges, and a push after approval waits for a new review. `dco` is outside the rule, unlike plan §11's `required`, `dco` and `pr-title`, because item commits stay unsigned until each milestone's gate; enforcing `dco` on `main` alone after the M0 gate would need a ruleset of its own. M0.3d names draft runs' aggregate `required (draft)`, so a draft run's result never satisfies the rule.
- **Versions.** All pins and version deviations (V1–V12) are listed once, under Version pins; ADR 0001 copies them and m0-gate.md §5 re-checks them.
- **Dev box.** Node 26.12.0 (official MSI, no corepack), pnpm 11.28.6 and per-user uv 0.13.1 are installed. Docker Desktop does not start at login. The owner enabled Developer Mode on 2026-10-17; non-elevated file and directory symlinks now work, so the symlink-privilege cases run locally. Git for Windows supplies `gpgv`; gpg is not required on PATH.
- **GitHub.** `draftyak/draftyak` was created on 2026-10-17 and became public on 2026-10-19. The owner selected `m0` as the working default branch on October 19; M0.41 returns it to `main` at the gate. The October 17 settings JSON is historical and records the earlier private/`main` state. Current protections and settings require dated owner-run gate evidence.
- **GitHub behaviour.**
  - `workflow_dispatch` and `schedule` use workflow files on the default branch, now `m0` under the October 19 decision, with the transition to `main` at the owner’s gate. Cross-OS spike runs keep the `spikes-run/**` push route.
  - Each job bills at least one whole minute; rebase-merge rewrites SHAs and the committer; `upload-artifact` drops the common path prefix (`spikes/`).
  - Standard arm64 runners (`ubuntu-24.04-arm`, `windows-11-arm`) work in private repos on the free minutes since 2026-01-29, so arm64 runs natively and QEMU is only a fallback. macOS labels: `macos-15` (arm64), `macos-15-intel`; `macos-14` retires 2026-11-02.
- **Toolchain behaviour on this box.**
  - TS 7 `tsc -b` rejects `.ts` import paths (TS5097) unless `rewriteRelativeImportExtensions` is set.
  - Turbo 2.x runs tasks in strict env mode, so undeclared variables (`DO_NOT_TRACK`, `DRAFTYAK_*`) never reach a task.
  - pnpm 11: an explicit `minimumReleaseAge` is strict (a version under 24 h fails non-interactive installs); `verifyDepsBeforeRun` defaults to `install`; `.npmrc` holds only auth and registry keys.
  - Vitest 5 doesn't search parent folders for a config, so each package has its own `vitest.config.ts`.
  - Node 26 can't spawn `.cmd` shims without a shell (ENOENT, EINVAL), and `shell: true` warns (DEP0190).
  - System32 bsdtar fails on symlink entries without Developer Mode (Node's Linux and macOS tarballs have `bin/npm` links); Git for Windows' gpgv reads a drive-letter `--keyring` path as a URL.
  - Node 26.12.0 adds `--allow-fs-vfs`, `--experimental-vfs` and `--vfs-load`; none is on §4's allowlist, and S2 tests them.

## Conventions for every M0 item
- **Branches.** The integration branch is `m0` (pushed by M0.7). Item branches are `mN-<nn>-<slug>` (e.g. `m0-01-workspace`, `m0-06a-spike-kit`), because git can't hold `refs/heads/m0` beside `refs/heads/m0/…`; each has a worktree `C:/dev/draftyak-wt/<branch>`, outside OneDrive. `tools/ci-checks` reads the item id from the branch. `spikes-run/<branch>-<UTC stamp>` branches live for one CI run (M0.8).
- **PRs.** A PR contains one backlog item or a group of related items. Before ready submission, run touched-package checks, `pnpm guard`, item acceptance and `pnpm adr` when changing an ADR. Affected CI controls need local negative/mutation checks with the required restricted-file exclusions. Applicable full/Windows CI provides ordinary PR full verification; syncs and owner gates retain local full verification. Rebase onto the current base before a new submission and resolve lockfiles through the package manager.
- **Merging.** Current-head required checks and reviewer approval enable GitHub rebase auto-merge into `m0`; a new head needs a new review. Only the owner performs milestone sign-off and the `main` transition under M0.41’s protected-push procedure.
- **Commits.** Author `Nick Savov <nicksavov@protonmail.com>`; conventional messages and PR titles (standard types plus `spike`). No `Signed-off-by`: the owner adds it at the gate, so `dco` is red until then. No attribution of any kind: no `Co-authored-by` trailers naming tools, and no statements about how work was produced, anywhere. `pr-meta` (M0.3) and `vendor-guard --commits` (M0.4) enforce it, and `commit-identity` (M0.3c) refuses any other author or committer email on the repository's own branches, and any other committer email on a gate PR.
- **Size.** The owner lifted the ~1,500-line PR guideline on 2026-10-18. `pnpm pr-size` reports counted source/configuration lines, separate totals for tests/fixtures, prose docs, lockfiles, wrappers, vendored files, vectors and evidence, and the raw total. S/M/L bands are informational and impose no submission maximum. The former prose-exemption gate question is removed; PR grouping remains limited to related items.
- **Owned paths.** Each item lists what it owns, and shared files are avoided by design: M0.1 declares every root script once; `tools/verify` has one file per step and profile, and CI runs those profiles, so no later item edits a shared list or `ci.yml`; `typecheck` runs per package (`turbo run typecheck`, each `tsc -b` on its own tsconfig); each spike owns `spikes/<id>/ci.json`; each Rust spike is its own Cargo workspace.
- **Secrets.** Only in the main checkout's git-ignored `C:/dev/draftyak/.env.live`, never in a worktree; `.env.live.example` lists names. Only the kit's `loadEnvLive()`, `saveEnvLive()` and `deleteEnvLive()` touch it; they find the main checkout through `git rev-parse --path-format=absolute --git-common-dir` (or `DRAFTYAK_ENV_LIVE`) and never print, log or snapshot a value. After each live session, spike tokens and grants are revoked at the vendor, their `DY_LIVE_*` entries are deleted, and the evidence records `revoked: yes`.
- **Telemetry.** `DO_NOT_TRACK=1` and `TURBO_TELEMETRY_DISABLED=1`, set by `tools/verify` and every workflow and passed into tasks by turbo (guardrail 8).
- **Shared machine.** Benchmarks, budgets and fixed-port tests (S7's port 1455) hold the kit's machine-wide lock and pass its idle check, or fail as `machine-busy`; evidence records machine load and concurrent builds. Everything else uses random ports and unnamed `--rm` containers.
- **Caches.** `DRAFTYAK_CACHE_DIR` (`C:/dev/.draftyak-cache`, outside the worktrees) holds Node binaries, Pyodide wheels and Docker staging copies; a shared `CARGO_TARGET_DIR` under it is optional (cargo locks it, so concurrent builds wait).
- **Windows spawning.** Never `shell: true`: pnpm runs as `process.execPath` plus `process.env.npm_execpath`, Vitest as `process.execPath` plus the resolved `vitest/vitest.mjs`, and turbo and Biome as the native executables from their platform packages.
- **Docker.** Vitest runs on the host. Containers run plain `node` scripts over `kit.stageForDocker()` copies (link-free, realpath-resolved, read-only), because pnpm's Windows junctions and win32-only native binaries don't work inside Linux containers.
- **Owner time.** Dated week-1 pre-tasks, then three batched sessions. An item marked **present** can't finish without the owner.

## Where spike code, kept tests, evidence and ADRs live
- **Packages.** One private package per spike, `spikes/<id>-<slug>` named `@draftyak/spike-<id>-<slug>`, never imported from `apps/`, `packages/` or `plugins/` (policy test): `kit` (M0.6a), `s01-sqlite3mc`, `s02-plugin-sandbox`, `s03-mcp-sdk`, `s03b-bridge-elicitation`, `s04-oauth-as`, `s05-desktop` (TS harness, Rust workspace `rust/`, Tauri app `tauri-app/`), `s06-slack`, `s07-siwc`, `s08-gmail`, `s09-messages-api` (neutral name, guardrail 3), `s10-mobile` (Rust workspace with the mobile app and `transport-skeleton`), `s11-python-runtime`, `s12-sms` (TS hub side and Gradle project `probe-android/`), `sched-clock` (TS tests, `jiff-check/`, `grit-check/`).
- **Test tiers** (file names, applied by the kit's Vitest factory):

  | Files | Script | Runs in | Needs |
  |---|---|---|---|
  | `*.test.ts` | `test` | `pnpm test`, every CI run | the lockfile only; offline |
  | `*.heavy.test.ts` | `test:heavy` | `verify:m0`, CI `full` (Linux-capable cases), `spikes-run` | Node binaries, Docker, browsers, Rust or long runs |
  | `*.live.test.ts` | `test:live` | owner sessions only | `.env.live` |
  | `*.device.test.ts` | `test:device` | S12 sessions only | ADB and the owner's phone |

  Scripts set their own flags (`node ../kit/run.ts --heavy`), so PowerShell and Git Bash behave alike; tags (`requires: symlink-privilege`, `requires: tauri-desktop`) route cases a host can't run. With `DRAFTYAK_STRICT_SKIPS=1` (`verify:m0`, `spikes-run`) a heavy test that can't run fails instead of skipping.
- **Evidence.** Content-free JSON in `spikes/<id>/evidence/`, written by `kit.writeEvidence()`: measurements as numbers, timestamps as ISO strings, environment fingerprints, status codes, field and header names. Header values are kept only for `*ratelimit*`, `retry-after` and `content-type`; vendor ids (Slack ids and `ts`, Gmail ids) only as per-session HMACs whose key is never stored; URLs as host plus document hash. vendor-guard enforces the shapes (M0.4). `spikes-run` uploads evidence, never an installable build, as 7-day artifacts; it is committed in the spike's ADR PR.
- **Kept tests** keep running in `pnpm test`, `verify:m0` and CI until the milestone in the ADR table absorbs them; that PR deletes the spike. `pnpm adr` fails an ADR whose Kept test section lacks the milestone and path.
- **ADRs.** `docs/adr/NNNN-<slug>.md`, never renumbered; a superseded ADR names its successor. Template `docs/adr/template.md`; `docs/adr/README.md` is written by `pnpm adr --index` at the gate. Header: `Status` (proposed | accepted | superseded), `Date`, `Spike`, `Plan`, `Owner decision` (yes | no). Sections in order: **Context**, **Options**, **Decision** (first line `Go`, `Go with fallback`, `No-go` or `Not run`, then the plan changes), **Fallback**, **Evidence**, **Kept test** (path, command, what it guards, destination).
