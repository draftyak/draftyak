# M8: local MCP

M8 follows the M3 vertical slice, with paired-device session acceptance requiring
M4. The approved MCP design, ADR 0004, ADR 0005 and the plan's M8 acceptance
define the complete milestone. Product source imports no spike implementation.
Local unit or archive results do not establish installed-client acceptance.

For the M8.4 packer, inputs are explicit already-compiled caller-supplied files
and a chosen new output. It imports only the merged public protocol JCS helper;
its tests directly declare the existing pinned schema validator. It imports no
hub, CLI, native service, unmerged contract or vendor-client implementation.
The existing workspace glob discovers its package; only its own lock importer
is added, with existing registry resolutions unchanged.

The generated summary deliberately reports `selfContained: "not-verified"`,
`runtimeExecution: "not-run"` and `clientAcceptance: "not-run"`. Actual bridge
contents and native runtime/installed-client behavior require their own gates.
Archive generation neither authenticates a user nor grants send/session rights.

Acceptance commands for this slice are:

```powershell
pnpm install --frozen-lockfile
pnpm --filter @draftyak/mcpb test
pnpm verify
pnpm guard
```

The source checkpoint passes 22 native Node cases without skips and unchanged
full Windows verification: 2,651 unit tests, 15 Rust tests and all seven steps.
Final documentation alignment uses the same unchanged submission profile and
file/commit guards. Real bridge build, bundle execution, supported-client checks
and complete M8/M8b/M9 acceptance remain open. The package
[workspace appendix](m8-mcpb-workspace.md) defines its dependency and payload
boundary; the packer notes specify deterministic archive and close-ownership
constraints without replacing these milestone gates.
