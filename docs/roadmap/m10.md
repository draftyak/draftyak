# M10 backlog: desktop packaging and recovery

The approved implementation plan's sections 7, 11, 12 and 13, with the desktop
pilot scope below, assign this milestone's work. Results belong in item PRs;
planned commands and paths do not claim an implementation or a passing gate.
M10 receives the retained product through m7 after the earlier owners' actual
merges and ordinary verified propagation. Postponed m7b, m8, m8b and m9 branches
are outside this active flow. Their gates are not M10 prerequisites.

## Desktop pilot scope

- Ship the desktop app and bundled hub on Windows, Apple-silicon macOS and
  Ubuntu 24.04, with Gmail, Slack, drafting and one-off exact-content/window
  scheduling. The desktop stays awake and running; a missed window requires
  fresh approval. Encryption, credentials, PIN approval, native authority,
  recovery and duplicate-send protections remain required.
- Build Windows NSIS, an ad-hoc-signed Apple-silicon DMG and Ubuntu 24.04 deb.
  MSI, Intel Mac, AppImage, mobile, Python, npm/Docker/headless distributions,
  context tools and MCP outputs are postponed. Preserve their item IDs and
  history; postponed acceptance is not a passing or required pilot gate cell.
- Bundle only `channel-gmail`, `channel-slack`, `ai-messages-api`,
  `ai-responses-api` and `ai-chat-completions`. `channel-hello` remains a contract
  fixture. No third-party installation, plugin-author kit, json-template send or
  update-check surface ships. Optional separately maintained general contracts
  are consumed only after their actual merge; unavailable contracts fail closed.
- Keep automatic in-place installer upgrades on all three selected OSes: stop
  the running hub, drain safely and preserve encrypted state and scheduled work.
  Add desktop **Back up now** with native save, approval and PIN. No automatic
  network update check or quit-first reduction is introduced.
- Publish desktop installers in an immutable GitHub Release only. Every actual publication
  needs the owner's explicit approval. No npm, Docker, PyPI, mobile or MCP
  publication is part of this pilot.

## Conventions and verification

Use TypeScript and the shared unit/heavy tiers. Native cases use their existing
OS requirement tags. Before a ready PR, run touched-package tests/type/build,
changed-file lint, item acceptance and `pnpm guard` with zero findings. Docs-only
changes use `node tools/verify/verify.ts --profile docs`. No blanket local full
`pnpm verify` is required. Changes to controls that decide CI execution, skips or
passes require affected local checks and boundary/mutation proofs; unrelated
full/platform suites use applicable exact-head CI. Review requires current
`required`, `pr-title` and exact-head approval. Owner sign-off supplies DCO at the
milestone gate. A docs-policy skip is never a full or platform pass.

Installer, upgrade, shutdown, restore and desktop-pairing tests use a separate
test identifier/product or named isolated `--profile`, data directory and
keychain service. Install per-user into a temporary folder with autostart off;
never reach the real running app. On success and failure, remove only that test's
uninstall entries, shortcuts, autostart entries, credentials and data, then check
for leftovers. Real-identity silent install/upgrade is confined to disposable
release runners. Native launch/mutation cases remain outside ordinary verify:
Rust integration cases use `#[ignore]`, and their strict heavy wrappers invoke
them explicitly with `-- --ignored`. M10.12 invokes those wrappers locally under
the shared-machine admission and bench-lock rules.

- **Goal:** diagnose the native Node process and optional data directory without
  opening or enumerating user data.
- **Inputs:** `tools/fetch-node/versions.json` and the plan's inspector,
  data-directory, environment-key and Temporal rules.
- **Outputs:** a TypeScript source-checkout command and importable fixed-code
  diagnostic report, initially with a private known-sync-folder predicate.

  package, public-listener check, artifact manifest or support bundle.
- **Acceptance:** `pnpm --filter @draftyak/doctor typecheck` and
  `pnpm --filter @draftyak/doctor test`; linked invocation reports and refuses
  correctly, while importing the entry does not execute it. Unsupported Node
  refuses before diagnostic import. Cover permission scopes, normalized positive
  and negative signal flags, and all configured OneDrive names. Known/configured
  synced paths fail with `DATA_DIR_SYNCED`. Aliases, malformed paths and unreadable
  metadata fail with their own fixed codes. Only `typeof Temporal === 'undefined'` warns for Temporal;

  appear in reports. Turbo hashes the external runtime policy; tests use Vitest.
- **Depends on:** merged M0 runtime policy and M1 package conventions. M10.11
  later replaces the private predicate after actual M2.11 propagation.
