# M10: packaging, headless operation and mobile

M10 follows M4. Complete acceptance requires reproducible product distributions,
installer upgrades that preserve encrypted state and pending schedules, real
headless service operation, release signing and supported mobile acceptance.
This candidate delivers M10.2's source tooling and the portable part of M10.3;
it does not contain a compiled product or declare the milestone complete.

| Item | Inputs and owned paths | Output and acceptance |
|---|---|---|
| M10.1 runtime acquisition and doctor | Authenticated pinned Node cache, explicit local artifacts; existing `tools/fetch-node/**` and separate doctor item | Verify official signed checksums and minimum Node 26.5.1; ordinary doctor remains a separate review. Bundle support is post-MVP. |
| M10.2 candidate assembly and inspection | Reviewed inventories, already-built local hub/CLI/native payloads and authenticated Node archives; `tools/bundle-hub/**`, `tools/release-guard/**` | Bounded held-file staging, deterministic inventory, complete artifact inspection and optional measured schedule oracle. Tooling is implemented here; current-product compilation/oracle and release acceptance remain open. |
| M10.3 portable package | An inventoried candidate plus M10.2 tools; `tools/packaging/**`, the packaging workspace importer | Deterministic npm archive, protected launcher, exclusive release-manifest output and inert service templates. This candidate supplies source and offline synthetic-fixture acceptance; real product installation remains open. |
| M10.4 native installers | Reviewed built desktop and product binding; platform packaging drivers | Per-target installers, installed-resource checks and upgrade/recovery acceptance. Open. |
| M10.5 headless deployment | Real portable product and owner-controlled dedicated service identity; Docker image/compose and service integration | Container/service startup, key-file protections, bind/health/shutdown checks and preserved scheduling. Only the independent `docker/draftyak` shell launcher and content-free `docker/healthcheck.mjs` are supplied here; no image is built or run. |

| M10.7 release gate | All accepted artifacts, authenticated provenance and owner/platform checks | Reproducible product builds, signatures, upgrade tests, native schedule equivalence and final release evidence. Open; a generated inventory or caller-supplied hash is not approval. |

No application, protocol, spike, CI policy or workflow source is included in
this tooling candidate. The lockfile adds only three workspace importers and
their two local package links; merged dependency resolutions remain unchanged.
Product modules referenced by the optional oracle are supplied explicitly from
a reviewed source checkout when that separate acceptance is eventually run.
The stored Cargo manifest is an inert template, materialized only in the
oracle's generated private workspace.

Acceptance on the final source uses the actual kit OS lock, at least eight GiB
of startup headroom and a continuous six-GiB floor:

```powershell
pnpm install --frozen-lockfile
pnpm --filter @draftyak/bundle-hub test
pnpm --filter @draftyak/release-guard test
pnpm --filter @draftyak/packaging test
pnpm --filter @draftyak/packaging test:heavy
pnpm verify
pnpm guard
```

The scoped heavy command installs and invokes only a synthetic local npm archive
with offline mode and lifecycle scripts disabled. It does not execute a native
fixture, actual product, service or vendor operation. The ordinary suite passes
2,821 unit tests, with one unchanged POSIX umask case skipped on Windows;
15 Rust tests and all seven default verification steps pass. The package suites
account for 67 bundle, 85 release and 40 packaging unit passes, plus the one
explicit offline npm heavy case. Final doc-only alignment requires the same
unchanged verification profile before submission.

The package READMEs define the input/output contracts. The foundation and
portable-component appendices describe the bounded reader, tar budget and
publication constraints; earlier validation there is historical. The combined
[candidate appendix](m10-portable-build-tools.md) records the genuine Cargo
manifest discovery failure and its fix without a policy exemption. Neither
synthetic archive tests nor historical donor binary measurements settle native
oracle, current-product, Docker, signing, upgrade or mobile acceptance.
