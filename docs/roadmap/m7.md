# M7 backlog: AI providers and routing

M7 supplies provider integrations and native per-account routing, disclosure,
consent, style notes and safe drafting triggers. PR #76 submits two standalone
completed-response cores. Actual transport, credentials, native execution,
other provider/auth adapters, UI and owner-controlled live gates remain open.

## Submitted scope and inputs

- `plugins/ai-messages-api/**` constructs and verifies a fixed request descriptor
  and validates an already completed response. It constructs no network client,
  reads no credential and has no stream accumulator.
- `plugins/ai-chat-completions/**` supports JSON-schema, JSON-object and Ollama
  formats. It checks endpoint metadata supplied by a trusted caller and invokes
  a required injected transport; it performs no DNS or network operation itself.
- The package configurations, generated workspace importers, tests and existing
  component notes accompany those cores. Shared contracts and native services
  are unchanged on the merged base.

The cores consume the merged provider, draft-output, canonicalization and hash
contracts. Compatible also uses the merged extension helpers. Transport inputs
and completed bodies are bounded snapshots; that does not cap an upstream
stream accumulated before admission. Trusted resolution metadata, a matching
request descriptor and a validated draft confer no native egress permission.
Native code must obtain current account, endpoint, policy and credential facts.
