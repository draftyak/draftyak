# M7 backlog: AI providers and routing

M7 supplies provider integrations and native per-account routing, disclosure,
consent, style notes and safe drafting triggers. Earlier milestones supply the
shared contracts and compatible request/response core. Actual transport,
credentials, native execution, SDK mounting, UI and owner-controlled live gates
remain separate acceptance work.

## Delivery rules

Each implementation starts only when its inputs are merged into its milestone
branch and its blocking owner decisions are recorded. Backlog entries describe
future work; they do not authorize starting blocked implementation. Item PRs
carry only their own changes, with shared contracts delivered through M1 first.
Before a ready PR, run a frozen install, checks for touched packages, applicable
offline acceptance targets and `pnpm guard`. CI supplies the full suites,
including Windows. A reviewer approves the submitted head and enables automatic
rebase merging after required checks pass. Milestone sign-off and publishing
remain owner-controlled.

Run Vitest directly with `--reporter=default` and exclude `**/*siwc*/**`,
`**/*siwc*`, `**/*dynamic-agent*` and `**/*dynamic_agent*` from these item checks.
For a package containing excluded sources, route check output through the
restricted-path log filter before reading it. Separate external acceptance
remains the responsibility of its own items.

The gate record (`docs/roadmap/m7-gate.md`) is written at the gate, after the gate
review. M7.8 delivers the acceptance driver, verification profile and owner
procedure that precede that record.

## Scope and inputs

- `plugins/ai-messages-api/**` constructs a fixed request descriptor
  and validates an already completed response. Its checked pinned-SDK factory
  requires injected fetch and uses a fixed placeholder; it resolves no credential
  and has no network fallback. The factory and non-parsing format do not mount a
  provider or supply a bounded native stream accumulator.
- M3.5a owns the compatible request/response core used by M3.5. M7 adopts it in
  `plugins/ai-chat-completions/`, supplies the plugin/SDK mount and presets, and
  consumes the shared routing classifier's current result. M7 does not create a
  second core or a parallel endpoint classifier/HTTPS rule.
- M7.9 owns only `plugins/ai-responses-api/`'s API-key adapter, including its
  completed-response conversion. Native stream accumulation is M7.4's work.
- The package configurations, generated workspace importers, tests and existing
  component notes accompany those cores. Shared contracts and native services
  are unchanged on the merged base.

The providers depend on the shared provider, draft-output, canonicalization and
hash contracts; compatible also uses the shared extension helpers. Transport inputs
and completed bodies are bounded snapshots; that does not cap an upstream
stream accumulated before admission. Trusted resolution metadata, a matching
request descriptor and a validated draft confer no native egress permission.
Native code must obtain current account, endpoint, policy and credential facts.
M2.19 owns the canonical field/value verifiers in its protected broker modules.
It builds every pin and descriptor from hub state and the merged contracts;
it does not import a later M3/M7 package or accept a plugin-selected verifier.
Provider package checks exercise actual constructed requests against that
accepted broker surface after the dependency reaches their milestone branch.

merged `AI_HTTP_PROFILES`, with `verify(request, pin, input)`. Its owner supplies

M2.26 owns credential references, the single refresh coordinator and
